# سیاست مهاجرت پایگاه‌داده

## چارچوب

- مهاجرت‌ها مبتنی بر `PRAGMA user_version` هستند (انتخاب ساده‌ترین تفسیر — فرض A-005).
- هر مهاجرت: نسخه عددی افزایشی، نام، SQL نسخه‌دار — در `MIGRATIONS` رجیستری فقط‌افزودنی.
- اجرا داخل تراکنش: یا کامل اعمال می‌شود یا هیچ.
- مهاجرت ۱ (ساخت اسکیما) نیازی به بکاپ ندارد؛ مهاجرت‌های بعدی که روی داده موجود تغییر ساختار می‌دهند **پرخطر** هستند.

## قواعد

1. **بدون از دست رفتن داده**: هیچ مهاجرتی ستون داده‌دار را حذف نمی‌کند؛ ستون‌های منسوخ فقط کنار گذاشته می‌شوند.
2. **بکاپ قبل از مهاجرت پرخطر**: قبل از اجرا، callback بکاپ صدا زده می‌شود؛ شکست بکاپ = توقف مهاجرت.
3. **سازگاری رو به جلو فقط با نسخه پایین‌تر ممنوع نیست** — بکاپ‌ها همیشه قابل بازیابی در نسخه فعلی می‌مانند.
4. نسخه اسکیما همیشه با `DATABASE_SCHEMA_VERSION` قراردادها همگام است.
5. عدم همگامی نسخه = توقف راه‌اندازی با خطای 1102 (نه اجرای حدس‌آمیز).

## سناریوهای بازیابی

- قطع‌شدن حین مهاجرت → تراکنش rollback می‌شود → user_version دست‌نخورده → اجرای مجدد ممکن.
- خرابی پایگاه‌داده حین مهاجرت → بازیابی از آخرین بکاپ + اجرای مجدد مهاجرت.
