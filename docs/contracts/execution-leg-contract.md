# قرارداد پا و اجرا — Execution & Leg Contract (نسخه ۱)

## تعریف‌ها

| مفهوم | تعریف |
|---|---|
| Execution | فیل واقعی بروکر (واردشده یا دستی) — موجودیت سطح پایین |
| Entry Leg | رویداد معنایی ورود — می‌تواند چند Execution داشته باشد |
| Exit Leg | رویداد معنایی خروج — می‌تواند چند Execution داشته باشد |

## قواعد

1. هر Execution دقیقاً به **یک** پا تعلق دارد؛ هر پا می‌تواند چند Execution داشته باشد.
2. معامله دستی → ساخت Execution دستی و اتصال خودش به پا.
3. داده واردشده (import) → اول `SourceRecord` (غیرقابل تغییر، با هش)، بعد `Execution`، بعد تخصیص به پا.
4. اجرای بدون پا → وضعیت `needs_assignment`؛ در PnL و R محاسبه نمی‌شود تا کاربر تخصیص دهد.
5. تخصیص از طریق `AssignExecutionToLegCommand` انجام می‌شود و در حسابرسی ثبت می‌گردد.
6. حجم پا = جمع حجم اجراهای آن پا؛ میانگین قیمت پا = میانگین وزنی حجمی.
7. پاها حذف سخت نمی‌شوند؛ وضعیت فعال/غیرفعال دارند و تاریخچه‌شان حفظ می‌شود.
