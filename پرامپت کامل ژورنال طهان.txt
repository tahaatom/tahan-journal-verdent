
# ۱) قانون کلی استفاده از این پرامپت‌ها

روش صحیح ارسال به هوش مصنوعی:

1. ابتدا **پرامپت مادر** را ارسال کنید.
2. از هوش مصنوعی بخواهید فقط تأیید دهد که معماری و قوانین را فهمیده است.
3. سپس **فاز ۰** را ارسال کنید.
4. بعد از تکمیل فاز ۰، فازهای بعدی را یکی‌یکی ارسال کنید.
5. بعد از هر فاز، **پرامپت کنترل کیفیت** را ارسال کنید.
6. تا زمانی که فاز قبلی کامل نشده، فاز بعدی را ارسال نکنید.

DOMAIN CONTRACTS:

Journal Trade in version 1:
- belongs to exactly one trading account
- belongs to exactly one symbol
- has exactly one direction: buy or sell
- can have multiple Entry Legs
- can have multiple Exit Legs
- can have multiple Executions
- has exactly one implicit Position Group in version 1
- multiple independent trading decisions must be separate Journal Trades

Position Group:
- reserved in version 1
- explicitly implemented in version 2

Execution and Leg:
- Execution is a real broker fill
- Entry Leg is a semantic entry event
- Exit Leg is a semantic exit event
- each Leg may contain one or more Executions
- each Execution belongs to exactly one Leg
- manual trades must create manual Executions
- imported data must first become SourceRecord, then Execution, then assigned to a Leg
- unassigned Executions must be marked as needs_assignment
- unassigned Executions must not be used in PnL or R calculations

R calculation:
- R is a unit of initial accepted risk
- multiple entries use volume-weighted average entry price
- initial stop loss is the basis for risk
- moving stop loss later does not change initial R basis
- if no stop loss exists, RiskCalculationStatus = no_stop_loss and automatic R is not calculated
- user may enter manual risk; then RiskBasis = manual_risk
- commission and swap must be deducted from realized PnL
- for multiple exits, total net realized PnL is divided by initial risk amount
- ExitLegR may be calculated per exit, but TradeR is based on total net result
- MAE/MFE fields are reserved in version 1 and activated in version 3 when sufficient price path data exists

DATA LAYERS:

1. Raw Source Data
- immutable

- hash tracked

2. Canonical Data
- normalized journal data
- editable through official commands

3. Override Ledger
- manual corrections
- preserves previous value, new value, reason, time, source, priority, reversibility

4. Effective Data
- final data used for display, filter, stats
- derived from canonical data plus overrides

5. Analytical Projection

- regenerable

- Audit logs for sensitive operations

- Technical trade save: P95 < 300 ms
- Fast user trade entry scenario: P95 < 15 seconds
- Full trade entry scenario: P95 < 60 seconds
- Simple filter: P95 < 500 ms
- Combined filter: P95 < 800 ms
- Trade list with 100,000 synthetic records must remain usable
- Import 1000 records: under 10 seconds
- Full backup: under 30 seconds
- Full restore: under 60 seconds

# ۱۲) مقایسه روش‌های ارسال و توصیه نهایی

| روش | مزایا | معایب | توصیه |
|---|---|---|---:|
| ارسال کل پرامپت‌ها در یک پیام | سریع به نظر می‌رسد | هوش مصنوعی دچار فراموشی، خطا و پرش بین فازها می‌شود | اصلاً توصیه نمی‌شود |
| ارسال پرامپت مادر سپس همه فازها به‌صورت فهرست | دید کلی می‌دهد | هنوز خطر اجرای سطحی وجود دارد | متوسط |
| ارسال پرامپت مادر، سپس فاز به فاز، سپس کنترل کیفیت بعد از هر فاز | بیشترین دقت، کمترین خطا، قابل اشکال‌زدایی | زمان‌برتر | بهترین گزینه |

## گزینه برتر

**ارسال پرامپت مادر + پرامپت جلوگیری از خطا + سپس فاز به فاز + کنترل کیفیت بعد از هر فاز**

### دلیل برتری:

1. هوش مصنوعی در هر لحظه فقط روی یک محدوده مشخص تمرکز می‌کند.
2. قراردادها در هر فاز حفظ می‌شوند.
3. خطاها زود کشف می‌شوند.
4. معماری خودسرانه تغییر نمی‌کند.
5. هر فاز قبل از فاز بعدی قابل تست است.
6. احتمال تولید نرم‌افزار پایدار بسیار بالاتر می‌رود.

# جمع‌بندی نهایی

برای پروژه **ژورنال طهان / کرنل آریا**:

- مبنای نهایی: **سند نسخه ۵**
- معماری: **موتورهای مجزا + قرارداد-محور + پلاگین‌های کنترل‌شده**
- استک: **Rust + Tauri 2 + SQLite/SQLCipher + React/TypeScript + Python Sidecar**
- روش اجرا: **فاز به فاز، قرارداد به قرارداد، تست به تست**
- هدف: **ساخت نرم‌افزاری پایدار، آفلاین، فارسی، راست‌به‌چپ، امن و قابل توسعه برای سال‌ها**

این پرامپت‌ها به‌گونه‌ای طراحی شده‌اند که هوش مصنوعی بتواند با کمترین ابهام، کمترین خطا و بیشترین پایبندی به معماری، پروژه را از فاز ۰ تا فاز ۵.۵ پیاده‌سازی کند.
